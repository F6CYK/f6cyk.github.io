# Refonte de l'architecture documentaire

La période couverte par ce document ne s'est pas limitée au développement
du menu récursif.

Une refonte progressive de l'ensemble du site a été engagée afin de faire
évoluer le projet vers une architecture documentaire homogène, modulaire
et facilement extensible.

Cette évolution est désormais considérée comme acquise et ne devra plus
être remise en cause.

------------------------------------------------------------------------

# Principes généraux retenus

Les développements suivent désormais les principes suivants :

- séparation stricte entre contenu et présentation ;
- séparation entre données, composants Liquid et feuilles de style ;
- réutilisation maximale des composants ;
- absence de duplication de code ;
- organisation documentaire indépendante de la présentation graphique ;
- compatibilité complète avec GitHub Pages.

Ces principes constituent désormais le cadre de développement.

------------------------------------------------------------------------

# Composants génériques validés

Plusieurs composants réutilisables ont été créés.

## intro.html

Ce composant réalise la présentation normalisée d'une page documentaire.

Il reçoit notamment :

- le contenu d'introduction ;
- une illustration ;
- une légende.

Toutes les nouvelles pages devront utiliser ce composant.

## figure.html

Les illustrations sont désormais centralisées au sein d'un composant unique.

Ce composant remplace les insertions HTML spécifiques.

## flipbook.html

Le composant permet l'affichage interactif d'une documentation PDF.

Le chemin du document est construit automatiquement à partir de :

    {{ page.asset_path }}/{{ include.file }}

En conséquence, seul le nom du fichier PDF doit être transmis.

Toute transmission d'un chemin complet est proscrite.

------------------------------------------------------------------------

# Organisation documentaire des matériels

Une nouvelle organisation documentaire est désormais retenue.

Chaque matériel possède son propre répertoire contenant l'ensemble de sa
documentation.

Exemple :

    materiel/
        transmissions-militaires/
            trc3600/
                trc3600.md
                trc3600.jpg
                Thales_TRC3600_HF_Combat_Radio_Datasheet.pdf

Chaque dossier constitue une unité documentaire autonome.

Cette organisation est validée.

# Évolution de la navigation

Le menu principal a atteint un niveau de complexité qui rend son évolution
peu souhaitable si toutes les rubriques continuent à être codées directement
dans `_includes/menu.html`.

La solution retenue consiste à adopter la même philosophie que celle déjà
utilisée pour la documentation.

Le développement futur reposera sur un nouveau fichier :

    _data/materiel.yml

Le menu « Matériel » devra être généré récursivement au moyen du composant
déjà existant :

    recursive-menu.html

Cette orientation est validée.

------------------------------------------------------------------------

# Contraintes de développement

Les développements devront continuer à respecter les règles suivantes :

- une seule modification fonctionnelle par itération ;
- validation systématique avant toute évolution ;
- aucune régression admise ;
- conservation des composants génériques ;
- compatibilité permanente avec GitHub Pages et Jekyll 3.10.

------------------------------------------------------------------------

# Point de reprise

La prochaine étape du développement consistera à :

1. créer `_data/materiel.yml` ;
2. migrer la rubrique « Matériel » vers une génération pilotée par les données ;
3. conserver `recursive-menu.html` comme composant unique de génération des menus ;
4. poursuivre ensuite l'enrichissement des familles documentaires sans modifier
   l'architecture générale.

# Évolution du menu

Constat :

Le fichier `_includes/menu.html` ne doit pas devenir le point de maintenance principal.

Décision validée :

Créer un fichier :

    _data/materiel.yml

Le menu « Matériel » sera généré par :

    {% include recursive-menu.html noeuds=site.data.materiel %}

Le composant `recursive-menu.html` sera réutilisé comme pour `documentation.yml`.

---

# Choix d'architecture

- privilégier les fichiers YAML ;
- conserver les composants génériques ;
- éviter le HTML codé en dur ;
- une modification à la fois ;
- validation avant poursuite.
